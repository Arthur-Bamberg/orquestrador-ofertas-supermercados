# Redis key layout: JSON entities plus secondary indexes

Persistence uses plain Redis string values holding JSON documents and minimal secondary indexes — no RedisJSON module. Entity keys are `{tipo}:{id}` (e.g. `produto:{uuid}`). Collection SETs `mercados` and `fontes` hold ids for List. Produto and Marca resolve via `produto:norm:{nomeNorm}` and `marca:norm:{nomeNorm}` → id. Documento identity maps through `documento:id:{fonteId}:{filename}:{dia}` → id. Discovery days for a filename on a Fonte live in SET `documento:dias:{fonteId}:{filename}` (ADR 0028 primeira descoberta). Documento JSON carries the PDF content fingerprint; lookup for identical content walks prior days for that Fonte+filename (ADR 0036). Ofertas are unique catalog entities (`oferta:{id}`) with a uniqueness index from the Oferta key; Documento↔Oferta is N∶1 via association lists (ADR 0036), replacing the older “JSON array owned only by Documento” shape for Ofertas. Falhas de Extração for a Documento remain in `falhas:documento:{documentoId}` replaced wholesale on SaveAll (ADR 0017). Secondary SET `ofertas:produto:{produtoId}` indexes Oferta ids (and/or documentoIds as needed for readers) for that Produto. Uso do Extrator is one JSON per tentativa (`uso-extrator:{documentoId}:{tentativa}`) with SET index `uso-extrator:documento:{documentoId}` (ADR 0033). Operational Extrator quota skip keys use the app prefix `ofertas-scraper:extrator:{adapter}:esgotado:{yyyy-mm-dd}` (ADR 0037; workspace ADR 0002). Chosen over per-field HASHes for MVP simplicity on Upstash REST / SRH.
