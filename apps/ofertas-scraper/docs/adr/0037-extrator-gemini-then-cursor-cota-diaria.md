# Extrator auto: Gemini first, Cursor on rate-limit; daily adapter quota; Uso records provider

With `EXTRATOR_PROVIDER=auto` (default), DI wires a composite Extrator that tries Gemini first, then Cursor. Only rate-limit / quota signals (429, RESOURCE_EXHAUSTED, and equivalents) flip immediately to Cursor for that `Extract` and persist operational Redis keys `ofertas-scraper:extrator:{gemini|cursor}:esgotado:{yyyy-mm-dd}` in `America/Sao_Paulo` so later runs the same day skip the exhausted adapter. If a mid-`Extract` page hits Gemini quota, discard the partial Gemini result, mark Gemini exhausted for the day, and redo the whole Documento on Cursor. Uso do Extrator for the completing tentativa stores `provider` (`gemini` | `cursor` | `stub`) plus `model` and the existing token fields (ADR 0033). Non-quota Gemini outages (5xx, timeouts) keep job-scoped exponential backoff (ADR 0022) without setting the day flag. If Cursor is also rate-limited, mark Cursor exhausted for the day; when every available adapter is exhausted, Documentos that still need the Extrator end as `falhou` with no further attempts that day. Explicit `EXTRATOR_PROVIDER=gemini|cursor` still pins a single adapter. Supersedes the auto preference for Cursor in ADR 0023 / 0034.
